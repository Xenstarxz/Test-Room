01 ผลตรวจ Checklist เดิม 4 ข้อ

รายการสถานะหลักฐานการตรวจสอบ

02 พบใหม่ — ฟังก์ชันที่ควรอัปเกรด

เจอระหว่างตรวจ checklist เดิม ไม่ใช่บัคที่ทำให้ระบบพัง แต่เป็นฟีเจอร์ที่ "มีโครงไว้แล้วแต่ยังไม่ทำงานเต็มรูปแบบ"

high Onboarding Tour ถูกปิดไว้ (no-op)

src/utils/tour.js ทั้งไฟล์เหลือแค่:

export function startOnboardingTour() {
  // Tour disabled per user request
}
สถานะ: driver.js ไม่ได้อยู่ใน package.json เลย (ไม่ได้ติดตั้ง) แต่ UI เตรียม anchor point ไว้ครบแล้ว (data-tour="step-date", data-tour="nav-...") — เหมือนสร้างโครงไว้แล้วแต่ตัวทัวร์จริงถูกปิด ส่วน Tooltip "?" (อีกครึ่งของฟีเจอร์นี้) ทำงานปกติดี

mid advance_booking_days ยังไม่ถูกบังคับใช้

ตั้งค่าไว้ใน settings (ดีฟอลต์ 90 วัน) แต่ไม่มีจุดไหนใน bookings.js เช็คว่าวันที่จองเกินจำนวนวันล่วงหน้าที่กำหนดหรือไม่

เทียบกับ: blackout_dates / allow_bookings ที่ถูกบังคับใช้จริงแล้วในไฟล์เดียวกัน — เป็นแพทเทิร์นเดียวกับที่เคยเจอตอน seriesId ก่อนหน้านี้ (ข้อมูลพร้อมแต่ยังไม่ผูกใช้งานจริง)

low Endpoint ซ้ำซ้อนใน bookings.js

POST /series/:seriesId/cancel และ DELETE /series/:seriesId ทำงานเหมือนกันเป๊ะ แต่ frontend เรียกใช้แค่ตัวแรก

ผลกระทบ: ไม่กระทบการทำงาน แค่เป็นโค้ดที่ไม่ได้ใช้ ควร cleanup เพื่อลดความสับสนตอนแก้ไขในอนาคต

low ยกเลิก series แล้วเจ้าของไม่ได้รับ notification

endpoint อื่นๆ (เช่น admin ปฏิเสธ booking เดี่ยว) จะสร้าง in-app notification ให้เจ้าของเสมอ แต่ series-cancel ไม่สร้างเลย

ผลกระทบ: ถ้า admin ยกเลิก series ของ user คนอื่น เจ้าของจะไม่รู้เลยจนกว่าจะเข้ามาเช็คเอง — ไม่สอดคล้องกับ flow แจ้งเตือนที่ทำไว้ในจุดอื่น

03 ลำดับที่แนะนำให้อัปเกรด

1. ตัดสินใจเรื่อง Onboarding Tour ก่อนอื่น

ต้องยืนยันกับตัวเองก่อนว่า "ตั้งใจปิดไว้จริงไหม" — ถ้าใช่ ไม่ต้องทำอะไร ถ้าไม่ตั้งใจ นี่คือฟีเจอร์ high-priority ที่ยังไม่ทำงานจริง ต้องติดตั้ง driver.js แล้วเขียน logic จริงแทนฟังก์ชัน no-op

2. เพิ่มเช็ค advance_booking_days ใน bookings.js

เพิ่มเงื่อนไขเดียว เทียบวันที่จองกับ 今日 + advance_booking_days ก่อน insert — ใช้ pattern เดียวกับที่ blackout_dates ทำไว้แล้วได้เลย ไม่ต้องออกแบบใหม่

3. เพิ่ม notification ให้เจ้าของตอน series ถูกยกเลิก

เรียก createNotification() ที่มีอยู่แล้วในไฟล์เดียวกัน เพิ่มแค่ 1 บล็อกโค้ดในจุดที่ยกเลิก series สำเร็จ

4. ลบ endpoint ที่ซ้ำซ้อนออก

ลบ DELETE /series/:seriesId ทิ้ง เหลือแค่ POST /series/:seriesId/cancel ที่ frontend ใช้จริง

สิ่งที่ต้องเช็คก่อนอัปเกรดข้อ 1: ค้นหาในประวัติการทำงาน/บทสนทนาก่อนหน้านี้ว่าทำไม tour ถึงถูกปิดไว้ — คอมเมนต์บอกว่า "disabled per user request" ซึ่งอาจเป็นคำสั่งจริงที่เคยให้ไว้นอกบทสนทนานี้ ควรยืนยันความตั้งใจก่อนเปิดกลับมาใช้
